# Smart-Complaint-System-for-Businesses

Smart Complain is a SaaS complaint management platform that helps businesses collect, track, prioritise, and resolve customer complaints in a structured and professional way. It provides a lightweight embeddable widget that any business can add to their website with a single script tag. Customers use this widget to submit complaints directly from the business website. Those complaints appear in the business owner's dashboard where they can be reviewed, prioritised, and resolved efficiently.
The platform serves three types of users. Business owners get a full dashboard to manage complaints and view analytics. Customers get a simple, clean popup form to submit their issues without needing to send emails or call support. Platform administrators get a separate panel to oversee all businesses and complaints across the entire system.

The Problem This Solves
Most small and medium businesses handle customer complaints through WhatsApp messages, email threads, or informal notes. This creates serious problems. Complaints get lost. There is no way to track which ones have been resolved. There is no visibility into which issues keep repeating. There is no way to measure how quickly problems are being fixed. When complaints are not handled properly, customers leave without saying a word and write negative reviews online instead.
Smart Complain solves this by giving every business a dedicated complaint channel that is easy for customers to use and easy for owners to manage, with full visibility and data at every step.

Project Structure
index.html is the login and registration portal for business owners and admins.
style.css contains all styling for the login portal including layout, form design, animations, and responsive behaviour.
script.js handles form validation, view transitions, inline error messages, and user credential storage for the demo.
dashboard.html is the main business owner dashboard, built as a single-page application with views for complaints, analytics, settings, and integration guidance.
dashboard.css contains all dashboard styling including the navigation bar, complaint cards, priority badges, filter controls, and integration step layouts.
widget.js is the self-contained embeddable complaint widget. It has no external dependencies and injects everything it needs into any webpage it is added to.
widget-demo.html is a sample e-commerce site called TechStore demonstrating how the widget looks and works when embedded on a real business website.
admin.html is the platform-level admin panel for Smart Complain staff to manage businesses and complaints across the system.

Current Features
Login and Registration Portal
The portal opens with a role selection screen where the visitor chooses between Business Owner and Admin. Each path leads to a different login or registration flow.
New business owners fill a registration form collecting their business name, owner name, email, password, industry type, estimated monthly complaint volume, and phone number. The form checks for duplicate email addresses and shows a specific inline error if one exists. Successful registration creates the account and redirects to the dashboard. Existing users enter their email and password and are validated against stored credentials. A failed login shows a red inline error and triggers a shake animation on the form. Successful login shows a green toast notification and redirects to the dashboard.
Admin users have a separate login form that redirects to the admin panel. All view transitions use smooth fade and slide animations throughout.
Business Owner Dashboard
The dashboard is a single-page application with a deep blue navigation bar at the top and a light grey page background. It has four main sections.
Complaints View is the default view on load. It shows all incoming complaints as individual cards. Each card displays the complaint title, the submitting customer's name and email, the submission date, the complaint category, a short excerpt of the description, and a priority badge. Priority badges are colour-coded: Critical is red, High is yellow-orange, Medium is blue, and Low is green. Each card has a Resolve button. When a complaint has been processed by AI, a purple badge shows the AI-assigned category and a reasoning block below the description explains the priority decision. Two filter dropdowns above the list allow filtering by status and by priority without reloading the page.
Analytics View presents key performance numbers in a grid of stat cards showing total complaints received, total resolved, average resolution time, and average satisfaction score. The layout is built to accommodate charts and trend graphs once the backend is connected.
Settings View provides toggle switches for email, SMS, and browser push notification preferences, and a widget customisation panel where business owners set their brand colour, button label, widget position, and language. The embed code snippet at the bottom updates automatically as these settings change.
Integration View is a three-step guided flow. Step one displays the business API key with copy and regenerate buttons and a warning that regenerating breaks existing installations. Step two shows the full ready-to-use script tag with a one-click copy button. Step three displays a live iframe preview of the configured widget so owners can see exactly how it will appear before installing it.
Embeddable Widget
The widget is added to any website with a single script tag. Configuration is handled entirely through data attributes on that tag, requiring no additional JavaScript from the business.
The attributes control the API key that identifies the business, the label text on the floating button, the brand colour applied to the button and popup header, the screen position as either bottom-right or bottom-left, and the interface language. On page load the widget injects its own CSS and creates a floating button and a hidden overlay. Clicking the button opens an animated popup form. The form collects the customer's name, email address, complaint category selected from a dropdown, and a free-text description of the issue. All fields are required and validated before submission. An invalid email shows an error without closing the form.
On valid submission the button enters a loading state, the complaint is sent to the API, and a success screen with a green checkmark replaces the form. The popup closes automatically a few seconds later.
The widget fully supports English, Arabic with automatic right-to-left layout switching, French, and Spanish. Every label, placeholder, error message, and success text adapts to the selected language. The widget is keyboard accessible, closes on the Escape key, has proper ARIA labels for screen readers, and scrolls internally on small screens so it never overflows the viewport on mobile devices.
Admin Panel
The admin panel gives Smart Complain staff a platform-wide view of all registered businesses, their subscription plans, and account statuses. It shows all complaints submitted across every business on the system. Admins can suspend or reactivate businesses, view detailed business information, and view or manage any complaint on the platform. Platform-level analytics show aggregate numbers across all accounts.

How to Run Locally
No build tools, package managers, or servers are required for the current version. Download or clone the files into a single folder and open index.html in a browser to see the login portal. Open widget-demo.html to see the widget embedded on the sample TechStore site. For the widget to work without browser security warnings about local files, start a simple local HTTP server from the project folder using Python or any equivalent tool, then open the served address in your browser.

Future Roadmap
Phase 1 — Spring Boot Backend and PostgreSQL
The first major phase replaces the localStorage demo with a production backend. The chosen framework is Spring Boot using Java, which is a mature and widely adopted choice for building REST APIs at scale. The database will be PostgreSQL, a reliable open-source relational database well suited for complex queries and concurrent traffic.
All portal actions will connect to real API endpoints. Registration will trigger an email verification step before activating the account. Login will return a JWT token sent with every subsequent request to prove the user's identity. Widget complaint submissions will authenticate using the business API key in the request header.
Core database tables will include businesses storing account details and the API key, complaints storing each submission with full metadata and status tracking, users storing support agents and their roles, attachments storing file metadata linked to complaints, and notifications storing user alerts. Every complaint is linked to its business by ID ensuring full data isolation between tenants.
Phase 2 — File and Image Attachments
Customers will be able to attach photos, screenshots, and PDF documents to their complaints from within the widget. A drag-and-drop upload area will appear at the bottom of the form. Supported formats are JPEG, PNG, WebP, and PDF. The widget validates file size and type on the customer's device before uploading, shows thumbnail previews of accepted files, and displays a progress bar during upload.
On the backend, files go through server-side type validation that reads actual file contents rather than trusting the extension. Every file passes through antivirus scanning before storage. Clean files are stored in AWS S3 and their paths are saved in the attachments table linked to the complaint. Dashboard access to attachments uses time-limited signed URLs so files are never publicly accessible. Free plan businesses get three attachments per complaint up to five megabytes each. Pro plan allows ten attachments up to twenty megabytes each. Enterprise plans have no limits.
Phase 3 — AI-Powered Classification
When a complaint is saved, a background job sends the complaint text to a large language model API. The model assigns a category if the customer did not select one, sets a priority level based on the urgency and tone of the language, generates a one-sentence reasoning summary, and flags complaints containing legal threats, safety concerns, or abusive content for immediate escalation. Results are written back to the complaint record and pushed to the dashboard in real time through a WebSocket connection without requiring a page refresh.
The AI also suggests a draft reply for the business owner based on the complaint category and how similar past complaints were resolved. The owner can edit it before sending or ignore it entirely. This reduces triage time significantly for businesses handling high complaint volumes.
Phase 4 — Spring Security
Authentication will be built on Spring Security using JWT. Login returns a short-lived access token expiring after fifteen minutes and a longer-lived refresh token stored in an HttpOnly cookie that JavaScript cannot read. When the access token expires the browser silently fetches a new one, keeping the user logged in without re-entering credentials.
Role-based access control will enforce that owners have full access within their account, agents can view and resolve assigned complaints but not access billing, viewers have read-only access, and platform admins have unrestricted access across all accounts. API keys are hashed before storage so the raw key never exists in the database. Each key has enforced hourly rate limits and a domain whitelist so the key cannot be used from unauthorised websites. Accounts lock after five consecutive failed login attempts. All admin actions are written to an audit log with timestamp, identity, and IP address.
Phase 5 — Scalability
The backend is fully stateless so any number of Spring Boot instances can run behind a load balancer and handle requests interchangeably. The PostgreSQL database will use read replicas to separate the high volume of dashboard read queries from write operations. Redis will cache expensive analytics aggregations so repeated requests are served from memory in milliseconds. AI classification, file processing, and email notifications are handled asynchronously through a message queue so complaint submissions are never delayed by heavy background operations.
The widget JavaScript file will be served from a content delivery network with servers distributed globally, bringing load time under fifty milliseconds for users anywhere in the world. Performance targets for the full production system are complaint submission response under two hundred milliseconds, dashboard load under one second for accounts with ten thousand complaints, and monthly uptime of 99.9 percent.

Business Model and Profitability
Smart Complain runs on monthly and annual subscriptions at four tiers.
The free plan covers up to one hundred complaints per month with basic features. It removes the financial barrier to entry and grows the install base. Every free installation is also passive marketing because the widget footer displays Smart Complain branding visible to every customer who uses it.
The Starter plan targets small businesses and adds AI classification, draft reply suggestions, and team member access. The Pro plan targets medium businesses with higher complaint volume and adds advanced analytics, longer data history, and more attachment capacity. The Business plan supports multiple websites or brands under one account with unified reporting. The Enterprise plan is custom-priced with dedicated infrastructure, formal SLA commitments, compliance features, and direct implementation support.
Beyond subscriptions, revenue comes from overage fees when businesses exceed their monthly limit, white-label licensing for agencies who resell the platform under their own brand, and professional services for enterprise onboarding and custom integration work.
The unit economics are favourable because the marginal cost of adding a new customer is very low once the platform is built. Infrastructure costs grow slowly while revenue grows with the customer count. High switching costs keep churn low: once a business has embedded the widget, trained staff on the dashboard, and accumulated months of complaint history, moving to a different system is costly and disruptive. Long customer lifetime combined with low serving cost produces strong margins that improve further at scale.

Why Smart Complain Works for Startups and Growing Businesses
For early-stage startups, a professional complaint channel from day one builds customer trust without requiring engineering resources. The free plan makes it accessible immediately. Complaint data reveals the exact friction points in the product or service, providing product teams with clear priorities without needing to run separate research.
For growing businesses adding support staff, the team workspace features, complaint assignment, and agent performance tracking scale naturally with headcount. No custom development is needed to accommodate growth.
For large businesses, the risks around complaints are more severe. A missed high-priority complaint can escalate to regulatory action or public reputational damage. Smart Complain's audit trail, escalation flags, SLA tracking, and analytics reduce that risk substantially and provide documentation if any complaint ever becomes a formal dispute. Because the core workflow of receive, classify, assign, and resolve is universal, the platform works equally well across e-commerce, healthcare, finance, education, and technology companies.

Technology Stack
The current frontend uses HTML5 for structure, CSS3 with custom properties, flexbox, grid, and animations for styling, and vanilla JavaScript with no external libraries for all interactivity. The Inter typeface is used throughout for clean typography.
The planned production stack uses Spring Boot 3 with Java 21 for the backend API, Spring Security with JWT for authentication, PostgreSQL 16 as the primary database, Spring Data JPA with Hibernate for database access, Redis for caching, AWS S3 for file storage, RabbitMQ for asynchronous job processing, a large language model API for AI features, a content delivery network for widget distribution, Docker and Kubernetes for containerisation and orchestration, GitHub Actions for continuous integration and deployment, and Grafana with Prometheus for monitoring and alerting.
